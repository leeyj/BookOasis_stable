# 도서 이동/이름 변경 시 독서 기록(진척도) 보존 및 삭제 방지 패치

## 1. 버그 내역 및 현상
- **현상**: 책의 상위 폴더 이름이 변경되거나, 책이 다른 하위 카테고리 폴더로 이동되는 경우, 스캐너가 기존 도서 레코드와 그에 엮여 있는 독서 진척도(`user_progress`) 및 통계(`user_reading_log`)를 통째로 지우고 새로운 도서로 재등록함.
- **원인**:
  1. 기존 스캐너는 도서 식별 시 오직 `file_path` 값의 절대 일치 여부만 판별함.
  2. 파일이 다른 곳으로 이동하여 원래 경로에서 보이지 않게 되면 즉시 `DELETE FROM books` 처리되어 사용자가 공들여 기록한 독서 이력이 소실되는 치명적 한계가 존재함.

## 2. 영향도
- **영향**: 도서 라이브러리 정리 및 파일/폴더명 갱신 시, 사용자가 수개월간 책을 읽었던 누적 통계와 읽고 있던 페이지 인덱스가 유실됨.

## 3. 수정 사항
- **대상 파일**: [tools/scanner.py](file:///c:/project/media_server/tools/scanner.py)
- **조치 사항**:
  1. **도서 이동 자동 감지 레이어 구현**: DB 동기화 처리 직전에, 실제 파일시스템에서 유실된 경로 집합(`deleted_paths`)과 새로 발견된 경로 집합(`new_paths`)을 추출.
  2. **파일명 상호 대조**: `deleted_paths` 내 도서의 파일명(basename)과 `new_paths` 내 도서의 파일명을 비교하여 상호 매칭되는 대상을 특정.
  3. **경로 정보 업데이트**: 일치하는 파일이 감지될 시, 도서를 삭제하거나 신규 등록하는 대신 기존 도서 레코드의 경로를 `UPDATE books SET file_path = ? WHERE id = ?` 처리를 통해 새로운 경로로 직접 갱신.
  4. **캐시 데이터 보정 및 삭제 감시 차단**: 갱신된 도서 정보를 `db_books` 캐시 맵에 주입하고 `deleted_paths` 및 `new_paths` 집합에서 제거하여, 이후의 오동작(중복 신규 등록 및 삭제 감시 처리)을 원천 방지함.

## 4. 해결 확인 및 검증
- 수동 스캔 테스트 및 매핑 검증은 사용자 단독으로 원격지에서 진행 예정.
- 로컬 문맥 상의 파이썬 구문 에러가 없음을 컴파일러로 교차 검증 완료.
