# 원격 마운트(VFS) 경로 스캔 시 압축 파일 I/O 병목으로 인한 스캐너 행 방지

## 1. 버그 내역 및 현상
- **현상**: 구글 드라이브 등 원격 마운트(VFS) 라이브러리 경로에서 수동 또는 스케줄러를 통해 라이브러리 스캔을 실행하면, 스캐너가 물리 폴더 트리 탐색 이후 멀티스레드 풀 생성 단계에서 멈추는(Hang) 현상 발생.
- **원인**:
  1. 원격 FUSE 마운트 지점의 경우 대량의 압축 파일(`.zip`, `.cbz`) 내부 정보를 읽기 위해 `zipfile.ZipFile`을 생성하여 오프셋을 빌드하거나 첫 페이지 표지(Cover) 이미지를 강제 추출하는 작업은 막대한 원격 파일 API 호출과 네트워크 지연(I/O 병목)을 동반함.
  2. `MAX_SCANNER_THREADS=4` 설정에 따라 4개의 스레드가 동시에 원격 압축 파일 I/O를 개시하면서 FUSE 데몬 및 rclone VFS 마운트 자체가 응답 불능(Lock/Hang)에 빠짐.

## 2. 영향도
- **영향**: 원격 저장소 라이브러리(대용량 구글 드라이브 등)를 스캔할 때 전체 스캐너 프로세스가 무한 대기하게 되어, 라이브러리 등록/삭제/갱신 동기화가 불가능해짐.

## 3. 수정 사항
- **대상 파일**: [tools/scanner.py](file:///c:/project/media_server/tools/scanner.py)
- **조치 사항**:
  1. **원격 경로 자동 판별**: `is_remote_path(physical_path)`를 사용해 스캔 대상 라이브러리가 원격 저장소인지 확인.
  2. **무거운 압축 파일 I/O 생략**: 원격지 경로인 경우 `process_folder_task` 내부에서 압축 파일 내 바이트 오프셋 분석(`collect_zip_offsets_data`)을 생략하도록 우회 처리. (어차피 뷰어에서 처음 열 때 자동으로 실시간 오프셋 빌드 및 Fallback이 되므로 지장이 없음)
  3. **표지 추출 방식 우회**: 원격지인 경우 zip 파일 내부에서 첫 페이지를 강제로 추출하는 폴백(`get_series_cover_fallback`) 과정을 생략하고, 폴더 내 실물 `cover.jpg`나 YAML Base64 표지가 있을 때만 표지를 할당하도록 제한.
  4. **스레드 동시성 직렬화**: 원격지 라이브러리 스캔 시에는 `MAX_SCANNER_THREADS` 개수를 1개(싱글 스레드)로 제한하여 네트워크 동시 요청량을 줄임으로써 행 현상을 원천 방지함.

## 4. 해결 확인 및 검증
- 수정 소스 반영 및 원격 서버 재배포 (`python deploy.py`) 완료.
- 수동 스캔 기동 시 행 현상 없이 정상적으로 파일 스캔이 완료됨을 확인.
