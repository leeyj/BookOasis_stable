# 버그 트러블슈팅: 카테고리 삭제 성공 후 사이드바 목록 미갱신 조치 (category.js)

## 1. 버그 내역 및 현상
- **현상**: 사용자가 특정 도서 카테고리를 완전히 삭제하는 액션을 수행하여 성공했음에도, 사이드바 목록에 삭제된 카테고리가 그대로 남아 있는 현상이 발생했습니다. 사용자가 F5 키 등으로 강제 새로고침을 해야만 사이드바 목록에서 해당 카테고리가 비로소 사라지는 오동작이 식별되었습니다.
- **원인**:
  - `static/js/category.js` 파일 내 `triggerDeleteLibrary` 함수의 삭제 API 성공 콜백 로직 구조상의 결함이 원인이었습니다.
  - 현재 활성화되어 선택 중인 카테고리를 삭제한 경우, 화면 전환용 `selectCategory('history')`만 호출하고 사이드바 목록을 리로드하는 `loadLibraries()` 함수 호출을 분기문 조건 상에서 아예 누락하여 사이드바가 갱신되지 않았습니다.

## 2. 영향도
- **영향 범위**: 프론트엔드 카테고리 제어 스크립트(`static/js/category.js`).
- **영향 수준**: 중 (Medium) - 이미 삭제 처리된 무효한 카테고리가 화면에 버젓이 남아 있어 사용자에게 삭제 실패로 오인하게 만드는 등 부적절한 사용자 경험(UX)을 야기합니다.

## 3. 조치 및 수정사항
- **수정 소스 파일**: [category.js](file:///c:/project/media_server/static/js/category.js)
- **수정 내용**:
  - `triggerDeleteLibrary` 함수 내의 성공 분기 흐름을 전면 수정하여 일관성을 부여했습니다.
  - 카테고리 삭제 완료 시, 분기 여부와 상관없이 **무조건 `await loadLibraries()`를 먼저 호출**하도록 처리하여 사이드바에서 지워진 카테고리가 즉각 반영 및 삭제되도록 보장했습니다.
  - 그 다음, 현재 활성화되어 있던 카테고리가 삭제된 경우에 한하여 `selectCategory('history')`를 기동시켜 화면이 '최근 읽은 도서' 뷰로 부드럽게 튕김 없이 전환되도록 고쳤습니다.

## 4. 해결 확인 및 E2E 검증
- 수정 사항을 운영 서버(`192.168.0.20:5930`) 무중단 구동 환경에 빌드 및 배포 완료했습니다.
- 실제 사이드바 상에서 특정 카테고리를 삭제한 결과, 새로고침 없이 즉시 사이드바에서 카테고리가 삭제 및 갱신되며 지워진 타겟 화면 역시 안전한 역사(History) 뷰로 정상 리다이렉션 처리되는 것을 수동 교차 검증하여 완료하였습니다.
