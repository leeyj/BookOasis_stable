# 🐛 알라딘 메타정보 커버 이미지 WebP 포맷 변환 저장

## 1. 버그/개선 내역
- **현상**: 알라딘 메타데이터 검색 매칭 완료 후 "적용"을 실행하면 커버 표지 이미지가 `.png` 파일로 로컬 저장소에 저장됨. 하지만 서버/웹 앱 인터페이스에서는 커버 이미지를 `.webp` 파일로 불러오도록 구현되어 있어, 404 Not Found 에러가 발생하며 웹 UI에서 표지 이미지가 정상적으로 표시되지 않음.
- **원인**: `plugins/metadata/aladin.py` 플러그인의 `apply` 처리 로직에서 다운로드받은 커버 이미지의 확장자를 `.png`로 강제 지정하고, 별도의 포맷 변환 인코딩 과정 없이 원본 데이터를 그대로 덤프하여 파일 시스템에 저장하기 때문임.

## 2. 영향 범위
- 알라딘 메타데이터 검색 플러그인 (`plugins/metadata/aladin.py`)

## 3. 수정 사항
- **플러그인 수정** (`plugins/metadata/aladin.py`):
  - 파일 전체 경로의 해시를 통해 생성하는 파일명 및 확장자를 `book_{hash}.webp`로 변경함.
  - `Pillow` 라이브러리의 `Image` 및 `io` 패키지를 추가로 가져옴.
  - `urllib.request`로 다운로드받은 이미지 바이너리(`img_data`)를 `Image.open`으로 로드하여, `"WEBP"` 포맷(품질 80)으로 인코딩 변환 후 로컬 파일 시스템에 저장하도록 수정함.
  - WebP 변환 인코딩 도중 예외가 발생할 경우에 대비하여 원본 바이너리를 파일로 저장하고 에러 로그를 출력하는 Fallback 메커니즘을 적용함.

## 4. 해결 사항
- 알라딘 OpenAPI를 통해 매칭된 최신 도서 표지 정보가 서버 환경에 맞추어 `webp` 포맷으로 완벽히 변환 및 저장됨.
- 이로써 웹 프론트엔드 및 API에서 `.webp` 확장자로 서빙을 시도할 때 파일이 부재하여 발생하던 404 Resource Load 에러가 원천 차단되고, 표지 이미지가 즉각적으로 깨짐 없이 렌더링됨.
