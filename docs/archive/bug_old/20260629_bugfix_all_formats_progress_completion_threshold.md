# 🧠 [Bugfix] 모든 도서 포맷(ZIP, EPUB, TXT) 완독 판정 기준 오차 보정 수정

## 1. 버그 개요 (Issue Overview)
- **발생 환경**: 환경설정에서 '다 읽은 도서는 최근 읽은 도서에서 삭제' 옵션이 활성화된 상태에서 EPUB, TXT 또는 ZIP 도서를 거의 끝까지 열람 후 뷰어를 탈출할 때
- **장애 현상**: 도서를 끝까지 읽었음에도 데이터베이스에 완독 상태(`is_completed = 1`)가 반영되지 않아, 대시보드 및 보관함의 '최근 읽은 도서' 목록에서 해당 항목이 소거되지 않고 계속 남아있는 현상.

---

## 2. 영향도 분석 (Impact Analysis)
- 사용자가 다 읽은 도서들이 목록에 지속 적체되어, 최근 보고 있는 책들의 이력 모니터링 편의성이 훼손되고 UX 상의 지저분함을 초래하였습니다.

---

## 3. 원인 파악 (Root Cause)
- **EPUB 뷰어**: EPUB 리더는 100분율 백분율 위치(CFI 기반)로 진행률을 역환산해 전송합니다. 마지막 장 렌더링 시작부 cfi 기준 백분율이 대개 98~99%에서 고착되어 물리적 100%에 이르지 못하는 오차로 인해 `is_completed = 0`에 머물렀습니다.
- **TXT/ZIP 뷰어**: 스크롤 뷰 형태에서 브라우저 이미지 레이지 로딩이나 스크롤 인지 정밀도 차이로 인해 맨 마지막 1~2페이지 리소스의 서버 조회를 미처 거치지 않고 종료하는 경우, 마찬가지로 `pages_read >= total_pages` 엄격한 동치 조건문이 불발되어 완독 처리가 누락되었습니다.

---

## 4. 조치 사항 및 수정 파일 (Resolution & Code Changes)

### [MODIFY] [stream_service.py](file:///c:/project/media_server/services/stream_service.py#L125-L131)
- 진행률 기록 API의 완독 판단 로직에 **95% 수용 임계값(Threshold)**을 적용하였습니다.
- 단행본의 포맷(ZIP, EPUB, TXT)에 구애받지 않고, 총 페이지 대비 읽은 페이지 비율이 `95% 이상`에 도달하면 `is_completed = 1`로 안전하게 승인하여 데이터베이스에 완독 상태로 업데이트하도록 보완했습니다.

---

## 5. 최종 검증 (Verification)
- 환경설정 옵션을 켜고 임의의 ZIP 만화책 및 EPUB/TXT 도서를 열어 전체 분량의 96~97% 지점까지만 진행도를 전송하고 이탈하였습니다.
- 백엔드 데이터베이스의 `user_progress` 테이블 내 `is_completed` 컬럼이 `1`로 안정적으로 자동 승인되어 기록됨을 확인했으며, 새로고침 시 최근 읽은 도서 목록에서 해당 완독권들이 남김없이 완벽히 제거되는 것을 E2E 최종 확인하였습니다.
