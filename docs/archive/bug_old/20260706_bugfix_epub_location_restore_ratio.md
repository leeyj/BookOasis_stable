# EPUB 뷰어 진입 시 이어보기 위치 복원 비율 공식 오류 수정

## 1. 개요 및 증상
- **현상**: EPUB 도서를 열거나 상세 화면에서 [이어서 읽기] 버튼을 클릭해 감상 뷰어로 진입할 때, 이전에 읽었던 페이지 위치가 복원되지 않고 강제로 무조건 맨 처음 표지(1페이지)부터 열려 매번 수동으로 페이지를 찾아가야 하는 사용자 조작 장애가 발생했습니다.

## 2. 원인 분석
- **비율(Percentage) 연산의 고정값 모순**:
  - `_doInitEpubViewer` 내부에서 기존 코드는 저장된 감상 페이지(`pagesRead`)를 불러와 100분율로 계산하고자 `pagesRead / 100`을 적용했습니다.
  - 또한, `if (pagesRead > 0 && pagesRead <= 100)` 라는 불합리한 조건 스코프를 유지하고 있었습니다.
  - 이로 인해 실제 도서의 물리 총 페이지(`totalPages`)가 100을 넘어가는 순간(예: `pages_read = 120`)에는 **조건식을 통과하지 못해 위치 점핑(Jumping) 블록 자체가 완전히 무시**되어 첫 장으로 초기화되었습니다.
  - 100 이하의 페이지 번호일 때도 실제 전체 페이지 개수에 비례한 정상 비율이 계산되지 못해 엉뚱한 이전 지점으로 복원되었습니다.

## 3. 해결 방안
- [viewer_epub.js](file:///c:/project/media_server/static/js/viewer_epub.js):
  - CFI(콘텐츠 식별 키) 복원을 유도하는 백분율 분기 구조를 전면 리팩토링했습니다.
  - 도서의 유효한 전체 페이지 개수(`totalPages` 또는 `epubTotalPages`) 값을 분모로 두어 **`pagesRead / total` 비율 공식을 정상 회복**시켰습니다.
  - `pagesRead <= 100` 조건을 완전 소거하여 100페이지가 넘는 장편 EPUB 도서 역시 안전하게 감상 이력 퍼센티지에 비례하여 이전 위치로 튕김 없이 순간이동 조작이 가능하도록 완치했습니다.

## 4. E2E 검증 결과
- 150페이지가 넘는 장편 EPUB 도서를 감상하다가 뷰어를 닫은 후 [이어서 읽기]로 재입장 시, 실시간 감상 히스토리 페이지 지점에 오차 없이 100% 매끄럽게 안착 및 자동 복원됨을 최종 검증 완료했습니다.
