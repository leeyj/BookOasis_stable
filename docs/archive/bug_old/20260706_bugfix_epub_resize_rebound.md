# F12 개발자 도구 활성화 및 창 리사이즈 시 EPUB 첫 페이지 튕김 오류 수정

## 1. 개요 및 증상
- **현상**: EPUB 뷰어 감상 중 사용자가 키보드의 `F12` 키를 눌러 브라우저 개발자 도구(DevTools) 창을 열거나 닫아 창 크기가 바뀔 때, 또는 수동으로 브라우저 창의 너비/높이를 리사이즈할 때 원래 읽고 있던 본문 페이지 위치를 잃어버리고 강제로 무조건 맨 첫 장(표지)으로 화면이 초기화되는 장애입니다.
- **현상 2 (추가 결함)**: 스크롤 모드에서 책이 비동기 연쇄 렌더링을 시작할 때, 연속으로 아래에 챕터가 덧붙여지면서 높이가 길어짐에 따라 브라우저가 내부 리플로우(Reflow) resize 이벤트를 유발했습니다. 이를 리사이즈 복원 리스너가 오인하여 사용자가 창을 바꾸지 않았음에도 렌더링 중 책을 강제로 첫 장으로 이동시키고 진척도를 0%로 초기화하는 간섭 결함이 동반되었습니다.

## 2. 원인 분석
- **epubJS 내장 리사이즈 스크롤 유실 버그**:
  - epubJS의 `Rendition` 엔진은 브라우저 윈도우 크기가 변할 때 `ResizeObserver` 또는 자체 이벤트 리스너를 통해 `Rendition.resize()`를 기동하여 다단 컬럼 레이아웃 너비를 재배치합니다.
  - 그러나 scrolled-doc(스크롤) 및 paginated(페이지) 모드가 활성화된 특정 구조 하에서 `resize()` 가 돌 때, 현재 읽고 있던 위치 CFI의 복원 처리가 누실되거나 음수 바운딩에 걸려 스크롤 탑이 `0` (처음)으로 리셋되어 버리는 epubJS 오픈소스 자체의 고질적인 결함이 존재했습니다.
- **세로 높이 팽창(Reflow) 리사이즈와 진짜 창 너비 리사이즈 혼선**:
  - `window.addEventListener('resize')`는 단순히 창 가로 크기뿐 아니라, 돔 추가로 인한 세로 스크롤 높이 증가 등의 문서 팽창 과정에서도 브라우저 명세에 따라 resize 이벤트로 가로채기 당할 수 있습니다.
  - 이로 인해 책 로딩 꼬리물기가 한창 돌 때 첫 페이지 복구가 비정상 작동되어 감상 흐름을 가로막았습니다.

## 3. 해결 방안
- [viewer_epub.js](file:///c:/project/media_server/static/js/viewer_epub.js):
  - **가로폭 변화 감지 가드 (`lastWidth`) 장착**:
    - 리사이즈 이벤트 시작 지점에 `window.innerWidth === lastWidth` 조건식을 걸어, 가로폭이 변하지 않고 단순 높이 팽창으로 인한 리플로우 리사이즈가 터졌을 때는 리스너가 즉시 실행을 중단(`return`)하도록 완전히 방어막을 설계했습니다.
    - 진짜 가로폭 창 크기가 변경(F12 온오프 또는 창 크기 조작)되었을 때만 `lastWidth`를 갱신하고 백업 및 CFI 복원 연산이 기동하도록 분리했습니다.
  - **창 리사이즈 실시간 CFI 백업 및 강제 디스플레이 자동 복구**:
    - 모듈 전역에 `lastActiveCfi` 변수를 선언하고, `window` 객체에 `resize` 이벤트 관찰자를 얹었습니다.
    - 리사이즈가 일어나는 즉시 `epubRendition.currentLocation()`에서 사용자가 직전에 응시하던 유효한 **CFI(콘텐츠 식별 지점)를 메모리에 실시간 선제 백업**합니다.
    - 크기 조정이 끝난 시점(200ms 디바운스 디레이 적용)에 epubJS 내부 연산이 스크롤을 0으로 튕겨냈음을 확인한 즉시, **백업한 `lastActiveCfi` 위치로 강제 `epubRendition.display(lastActiveCfi)`를 트리거**하여 본래 보던 단락 위치를 매끄럽게 사수하도록 보정 장치를 구축했습니다.
    - 스크롤 모드인 경우 복구 완료 직후 `views.check(100000)`를 동시 가동해 스크롤 병합 상태를 정상 회복하도록 2중 방어 조치했습니다.

## 4. E2E 검증 결과
- EPUB 본문 중간 챕터를 읽던 중 F12 키를 눌러 우측/하단 개발자 도구를 마음껏 켜고 끄거나 창 크기를 자유롭게 변경해도, 화면 튐이나 1페이지 튕김 없이 기존 감상하던 줄(Line) 그대로 정확하게 위치가 박제 보존되는 것을 E2E 최종 확인 완료했습니다.
- 또한 스크롤 연속 모드에서 백그라운드 꼬리물기 렌더링이 돌 때 더 이상 첫 페이지로 오인 튕김 없이 끝까지 100% 매끄럽게 선제 병합 완료되는 것을 최종 검증했습니다.
