# TXT 소설 파일 로드 시 CP949 인코딩 깨짐 현상 수정

## 1. 개요 및 증상
- **현상**: 구글 드라이브(원격 드라이브) 등에 업로드된 한글 TXT 소설 중 완성형(CP949/EUC-KR) 인코딩으로 작성된 도서들을 로드할 때 한글이 깨져서 외계어로 표시되는 현상이 발생했습니다.
- **제약 조건**: 원격지 구글 드라이브가 읽기 전용(Read-Only)으로 마운트되어 있어 서버 측에서 파일을 UTF-8로 변환하여 저장할 수 없으므로, 메모리 로딩 및 전송 단계에서 실시간 보정이 필요했습니다.

## 2. 원인 분석
- 기존 스트리밍 서비스(`stream_service.py`)의 `get_txt_content` 함수는 `utf-8 ➔ cp949 ➔ euc-kr` 순으로 엄격한 예외 검사(`UnicodeDecodeError` 감지)를 하며 루프를 돌았습니다.
- 그러나 일부 한글 텍스트 도서들의 경우, 전체 파일 중 단 몇 바이트의 손상(깨진 데이터 또는 정체불명의 바이너리)이 포함되어 있으면 `UnicodeDecodeError`가 발생해 정상적인 `cp949` 디코딩 절차를 밟지 못하고 스킵 처리되어 최종적인 바이너리 폴백(`latin-1` 또는 `errors='ignore' UTF-8`)으로 수렴되어 버렸습니다. 이로 인해 한글 소설 본문이 전부 깨지게 되었습니다.

## 3. 해결 방안
- [stream_service.py](file:///c:/project/media_server/services/stream_service.py): 디코딩 복구 알고리즘을 4단계로 고도화하여 보완했습니다.
  1. **1단계 (UTF-8 Strict)**: 표준 UTF-8 도서는 예외 없이 엄격하게 감지하여 리턴합니다.
  2. **2단계 (CP949/EUC-KR Strict)**: 깨짐이 없는 표준 완성형 도서를 온전하게 파싱합니다.
  3. **3단계 (CP949 자비로운 Fallback - `errors='replace'`)**: 엄격한 완성형 디코딩에 실패한 파일에 대해, 깨진 일부 바이트만 대체 문자(``)로 치환하고 나머지 99.9%의 한글 텍스트는 정상 복원하여 로딩할 수 있도록 자비로운 복구 처리를 제공합니다.
  4. **4단계 (최종 Fallback)**: 바이너리 단위 복구.

## 4. E2E 검증 결과
- 손상 바이트가 부분 섞인 구글 드라이브 CP949 텍스트 소설 도서를 열었을 때, 강제로 UTF-8 무시 디코더로 떨어져 한글이 깨지던 현상이 완벽히 소거되고 정상적으로 매끄러운 한글 본문이 읽혀지는 것을 최종 확인했습니다.
