# 스캔 시 물리 이동/삭제 도서의 찌꺼기 데이터 정화 조치

## 1. 버그 내역 및 증상
- 사용자가 물리 디렉토리 상에서 도서를 다른 하위 폴더나 카테고리로 이동한 뒤 라이브러리 스캔을 수행하면, 이동된 새 도서는 성공적으로 인식되어 일반 보관함 카테고리에 신규 노출되지만, 기존 위치에 있던 레코드가 삭제 관리(휴지통)로 들어간 후 완전히 소거되지 않고 계속 데이터베이스에 `is_deleted = 1` 상태로 잔존해 용량을 낭비하는 현상 발생.
- 윈도우/리눅스 경로 구분자 불일치(슬래시 `/` vs 백슬래시 `\`)로 인해 스캐너의 파일 이동 감지 알고리즘이 매칭에 실패하면서, 책 정보가 두 개로 쪼개지는 현상이 원인이 됨.

## 2. 원인 분석
- **경로 구분자 불일치**: 스캐너가 물리 파일 트리에서 찾은 `found_file_paths` 경로는 로컬 및 VFS 환경에 따라 백슬래시(`\`)가 섞일 수 있으나, DB에 저장된 경로는 리눅스식 슬래시(`/`) 기반이어서 `detect_and_handle_book_movement`의 Basename 매칭 전 단계인 셋(Set) 연산 차집합 단계에서 매칭이 빗나감.
- **자동 정리 미흡**: 물리 파일 트리에서 완전히 삭제되거나 이동 매칭이 비활성화된 항목들(예: 이미지 폴더 `__folder__.imgdir`)이 휴지통(`is_deleted = 1`)으로 가는데, 휴지통 비우기를 명시적으로 수행하지 않는 한 DB와 로컬 `covers/` 저장소의 디렉토리에 그대로 축적되어 용량을 낭비함.

## 3. 조치 사항
1. **경로 비교 정규화 (`tools/scanner/sync_detector.py`)**:
   - `_normalize_path` 헬퍼 함수를 추가하여 스캐너 내부 비교 시점의 모든 물리 경로와 DB 경로를 슬래시(`/`) 형태로 표준화하여 Windows/Linux 이식성을 보존함.
   - 이동 감지(`detect_and_handle_book_movement`) 및 소프트 딜리트(`handle_deleted_books`) 내의 비교셋 연산이 완전하게 경로 정규화 매핑 하에서 이루어지도록 전면 리팩토링함.
2. **자동 영구 삭제 스케줄 추가 (대안 2)**:
   - `handle_deleted_books()` 함수 내에서 소프트 딜리트 처리 후, 휴지통 보관 기간이 7일 이상 경과한 소프트 딜리트 도서들을 감지하여 `books`, `user_progress`, `user_reading_log`, `book_offsets` 테이블 및 로컬 `covers/` 하위의 대표 이미지 파일까지 백그라운드 스캔 완료 시점에 완전히 자동 영구 삭제(하드 딜리트)하는 클린업 파이프라인 구현.

## 4. 해결 확인 및 영향도
- 대규모 도서 이동이나 삭제 시에도 경로 비교 실패로 인한 중복 조각화가 방지되며, 이동한 책의 기존 진척도 이력이 안전하게 유지됨.
- 휴지통에 보관된지 7일이 지난 오래된 도서 데이터는 스캐너 구동 시 자동으로 흔적 없이 하드 딜리트 정화되어 디스크 및 DB 용량 효율을 반영함.
