# 🐛 카테고리 경로 수정 시 구(Old) 파라미터 전달로 인한 재스캔 누락 장애 조치

## 1. 버그 및 성능 이슈 내역
- **현상:** 웹 UI의 카테고리 편집에서 기존 경로에 신규 경로를 추가(엔터로 분리)하여 저장하면, 스캔 요청 메시지는 정상 팝업되지만 실제 큐 워커가 동작할 때 새로 추가된 경로가 스캔 리스트에서 누락되어 동기화되지 않는 오류 발생.
- **원인:**
  1. 카테고리 수정(`edit_media_library`) API 실행 시, 해당 카테고리가 큐(`scanner_tasks`)에 이미 대기(`pending`) 중으로 올라가 있다면 중복 등록 방지 로직에 의해 신규 태스크 인큐가 무시(skip)됨.
  2. 이로 인해 **변경되기 전의 옛날 경로 인자가 담긴 과거 태스크**가 그대로 워커 루프에 의해 수행됨.
  3. 실행 헬퍼인 `run_scan_job`이 큐 파라미터의 `physical_path`를 맹신하고 그대로 스캔을 위임했기 때문에, 변경 후의 새 경로에 대한 인지가 불가능해짐.

## 2. 영향도
- **기능 누락:** 카테고리 경로 변경/추가 후 즉시 스캔이 최신 경로로 작동하지 않아, 신규 도서들이 색인되지 않고 누락되는 품질 장애 유발.

## 3. 수정 사항 (수정 소스 파일 목록)
- **[services/scheduler_service.py](file:///c:/project/media_server/services/scheduler_service.py)**
  - `run_scan_job` 함수 실행 초입부에 DB를 실시간 쿼리하여 `physical_path`를 재할당(Override)하는 방어 코드를 구현함.
  - 이로써 대기열에 담긴 큐 인자 정보와 무관하게, 스캔이 시작되는 즉시 데이터베이스 `libraries` 테이블의 최신 물리 경로 필드값을 동적으로 불러와 스캔을 지휘하도록 교정함.

## 4. 해결 사항 및 E2E 검증 결과
- **경로 무결성 보장:** 스캔 시동 시 DB 최신 경로를 100% 조회하여 반영하므로, 구 큐 태스크가 실행되더라도 실시간으로 바뀐 경로들이 모두 완벽히 스캔 대상으로 병합됨.
- **편집 후 즉시 탐색 성공:** 카테고리 경로 추가 저장 후 백그라운드 스캐너가 새로운 물리 폴더를 정상 감지하여 DB 색인을 정상적으로 완수함을 검증 완료.
