# 20260720 — 만화책 뷰어 책 전환 시 프리로드 잔상 노출 버그 수정 완료

## 버그 내역

### 현상
- A 책을 열람하다가 닫고 곧바로 B 책을 열어서 볼 때, B 책의 일부 페이지(예: 5페이지)에서 이전 A 책의 동일 페이지 이미지 잔상이 순간적으로 노출되었다가 다음 페이지로 넘어가는 현상 발생.

### 근본 원인
- 만화책 뷰어의 백그라운드 비동기 순차 프리로드 기능(`startSequentialPreload`)이 실행되는 도중, 사용자가 A 책을 닫으면 캐시 맵(`blobCacheMap`)과 대기열 큐는 비워짐.
- 그러나 이미 `fetch(url)` 단계에서 비동기 대기(Await) 중이던 단일 프리로드 태스크는 책이 닫힌 이후에도 백그라운드에서 살아 움직임.
- 이 대기 중이던 팩(A 책 이미지)이 뒤늦게 다운로드 완료되면서 `blobCacheMap.set(5, objectUrl)`에 A 책의 이미지를 박아넣음.
- 사용자가 B 책을 기동하여 5페이지를 요청하면, 캐시 맵에 아까 꼬인 A 책의 5페이지 Blob URL이 그대로 들어있어 이를 즉시 B 책으로 오인해 오렌더링함.

## 영향도
- 서로 다른 만화책/소설을 스왑해가며 연속 감상하는 멀티태스킹 사용자 경험을 크게 저해하고 일시적 이미지 유실 현상을 초래함.

## 수정 사항

### 수정 파일 목록

#### `static/js/viewer/renderer.js`
- `startSequentialPreload(pageList)` 루프 내에서, 비동기 호출 실행 직전과 `fetch` 완료 직후 시점에 **현재 전역 책 ID 컨텍스트(`state.currentBookId`)가 프리로드 시작 시점의 책 ID와 달라졌는지 검사하는 가드 구문 이식**.
- 만약 책 ID가 달라졌음이(즉, 닫혔거나 다른 책으로 전환되었음이) 감지되면 비동기 프리로드 루프를 즉시 폭파(`break`)시켜 이전 책의 잔상 이미지가 맵에 등록되는 레이스 컨디션을 원천 차단함.

## 해결 사항
- 이제 책을 교환하며 신속하게 켜고 끄더라도, 이전 감상 중이던 프리로드 이미지 찌꺼기가 새로운 책에 오염되어 잔상을 노출하는 결함이 완벽히 박멸되었습니다.
