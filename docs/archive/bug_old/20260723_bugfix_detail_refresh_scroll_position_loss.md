# 버그 내역

## 증상

대시보드 또는 카테고리 도서 목록에서 스크롤을 내린 후 책 상세 뷰로 진입하여 책을 읽고(뷰어 종료) 돌아오거나, 상세 뷰에서 시리즈 스캔/메타데이터를 적용한 후 뒤로가기(목록으로 복귀)를 눌렀을 때 목록의 이전 스크롤 위치가 유지되지 않고 카테고리/대시보드 최상단(`0px`)으로 복귀하는 현상.

## 영향도

- **대상**: 도서 상세 뷰 ➔ 뷰어 실행 후 복귀 / 시리즈 스캔 갱신 후 뒤로가기 시나리오
- **심각도**: Medium — 목록 스크롤 위치가 유실되어 사용자가 이전에 보고 있던 도서 카드 위치로 다시 스크롤해야 하는 불편함 발생.

---

## 원인 분석

1. **상세 뷰 재로드 시 스크롤 위치 오염**:
   - `static/js/modal.js`의 `openBookDetail()` 함수가 실행될 때마다 무조건 현재 화면의 스크롤 위치(`currentScrollY`)를 캡처하여 `state.scrollPositions['last_pos']`에 저장함.
   - 뷰어를 닫거나 상세 뷰 내에서 데이터를 갱신할 때 `openBookDetail()`이 재호출되는데, 이 시점의 스크롤 위치는 상세 뷰 상단(`0px`)이므로 기존 목록 스크롤 위치(예: `1500px`)가 `0px`로 덮어씌워짐(Overwrite).

2. **목록 복귀 시 0px 스크롤 복원**:
   - 덮어씌워진 `0px` 값으로 인해 `goBackToList()` 실행 시 목록 최상단으로 복원되는 버그 발생.

---

## 수정 사항

### `static/js/modal.js`
- `openBookDetail()` 시작 부분에 `isAlreadyOpen` (현재 상세 뷰가 활성화되어 있는지 여부) 검사 로직 추가.
- 목록/대시보드 뷰에서 상세 뷰로 **최초 진입할 때만** `.library-main-content` 및 window 스크롤 위치를 `state.scrollPositions`에 저장하도록 수정.
- 상세 뷰가 이미 열려있는 상태에서 뷰어 종료/데이터 갱신으로 `openBookDetail()`이 재호출될 때는 기존 목록 스크롤 위치를 그대로 보존.

---

## 해결 결과

- 상세 뷰에서 도서를 읽고 나오거나 시리즈 스캔을 진행하더라도 최초 목록의 스크롤 위치가 오염되지 않고 안전하게 보존됨.
- 뒤로가기 클릭 시 이전에 탐색하던 목록 스크롤 위치로 부드럽고 정확하게 복원됨.
