# manage.sh ps 의존성 소거 및 도커/네이티브 완전 호환 조치 결과 (Walkthrough)

도커 슬림 컨테이너 내부에 `ps` 패키지가 없을 때 기동 및 상태 점검 오류가 발생하던 현상을 표준 셸 내장 기술과 `/proc` 역추적을 이용하여 완벽하게 조치하였습니다.

## 변경 사항 (Changes Made)

### [Server Controls]

#### [MODIFY] [manage.sh](file:///c:/project/media_server/manage.sh)
- 프로세스 감지 방식 대대적 개선:
  - `check_pid_alive()` 헬퍼 함수를 기입하여 셸 내장 기능(`kill -0`)만으로 `ps` 패키지 없이 프로세스 실제 동작 여부를 판단.
  - `find_pids_by_pattern()` 헬퍼 함수를 통해 `ps` 명령어의 존재유무를 검사한 후, 없을 시 리눅스 커널의 `/proc/[PID]/cmdline` 데이터를 널 바이트 단위로 직접 검색하여 기동 중인 Gunicorn 및 스캐너 워커 프로세스를 정밀 검출하도록 우회 수단 구현.
  - 기존 스크립트 전역의 `ps -p` 및 `ps ax` 호출 부분을 신규 헬퍼 함수들로 모두 대체.

## 검증 결과 (Verification Results)

### 호환성 검증
- `ps` 유틸리티가 삭제되거나 작동되지 않는 최소한의 경량 도커 컨테이너 내부 셸 환경에서도 `sh ./manage.sh status` 및 `sh ./manage.sh stop` 명령어가 오류 메시지(`ps: command not found`)를 일절 유발하지 않고 가동 유무 판별 및 정상 종료 처리를 수행함을 확인 완료하였습니다.
- 로컬 우분투 네이티브(Bash) 환경에서도 기존 기동 및 감시 시퀀스가 아무런 부작용 없이 동일하게 잘 수행됨을 교차 검증하였습니다.
