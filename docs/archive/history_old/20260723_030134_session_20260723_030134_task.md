# task.md: 스캔 완료 후 Queue running 고착 및 다음 스캔 대기 버그 수정

## 1. 개요
DB 스캔 및 cleanup 로그(`[scan-end]`)까지 정상 출력되었으나, 웹 UI 스캔 예약 대기열(Queue)에서 해당 스캔 작업이 여전히 `실행 중(running)` 상태로 남아있고 다음 pending 작업이 진행되지 않는 버그 해결.

## 2. 원인 분석
1. **스캔 종료 후 신규 도서 이벤트/웹훅의 동기식 블로킹 (Sync Webhook Loop Blocking)**
   - `tools/scanner/engine.py`에서 `scan-end-cleanup` 완료 후 `detected_new_books`에 대해 `dispatch_standard_book_event` 및 `_dispatch_new_books_to_plugin_hooks`를 메인 스레드 동기 루프로 호출.
   - 감지된 신규 도서가 많을 때(예: 97건) 동기 HTTP 웹훅 요청이 수십~수백 회 누적되어 `_scan_library_internal` 반환이 무한 블로킹되거나 극심하게 지연됨.
2. **Scanner Queue Worker Completion 안전성 결여**
   - `services/scanner_queue.py`의 `run_scanner_worker_loop`에서 작업 결과 반영(`update_task_result`)이 `try...finally` 구조로 안전하게 보호되지 않음.
   - 예외 또는 블로킹으로 인해 completion 결과 반영 코드가 실행되지 않으면 DB `scanner_tasks`의 status가 `running`으로 고착되어 워커가 다음 대기 작업(`pending`)을 시작하지 못함.

## 3. 작업 계획
- [ ] `tools/scanner/engine.py`: 스캔 종료 후 웹훅 및 플러그인 훅 디스패치(`dispatch_webhook_event`, `dispatch_standard_book_event`, `_dispatch_new_books_to_plugin_hooks`)를 비동기 백그라운드 스레드로 격리하여 메인 스케줄러가 즉시 완료 처리되도록 수정.
- [ ] `services/scanner_queue.py`: `run_scanner_worker_loop`에서 작업 완료/실패 상태 갱신(`update_task_result`)을 `try...finally` 블록으로 확실히 보장하여 예외 발생 시에도 task status가 `completed`/`failed`로 전환되도록 조치.
- [ ] 검증: 스캔 완료 시 웹 UI Queue 대기열 상태가 즉시 completed로 전환되고 다음 queued 스캔 작업이 연속으로 실행되는지 확인.
- [ ] 버그 문서화 (`./docs/bug/YYYYMMDD_bugfix_scanner_queue_completion_hang.md`), `./docs/workflow.md` 업데이트 및 `./tools/collect_docs.py` 실행.
