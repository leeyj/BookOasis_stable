# EPUB.js 대체 가능성 비교 체크리스트

## 1. 현재 커스텀 EPUB가 이미 잘하는 것

1. 모바일 UX 최적화
- iOS/Android 분기와 터치/오버레이 동작을 서비스에 맞게 통제한다.
- 자동 전체화면, 뒤로가기, 오버레이 닫기 같은 모바일 불안정 지점을 직접 제어한다.

2. 이어읽기와 복원
- `epub_session` 기반으로 CFI/href/index/percent를 저장하고 복원한다.
- `progress-state`를 통해 서버/클라이언트 상태를 함께 참고한다.

3. 페이지/스크롤 혼합 경험
- 페이지 모드와 스크롤 모드를 모두 지원한다.
- 모드 전환 시 위치 복원을 별도로 처리한다.

4. 서비스 연동
- 서버에서 EPUB 메타/목차/챕터/이미지를 분리 제공한다.
- 최근 읽은 책, 시리즈 카드, 상세 화면과의 연동이 강하다.

## 2. epub.js가 아직 더 강한 영역

1. 표준 EPUB 호환성
- 다양한 EPUB 구조와 예외 케이스를 폭넓게 처리한다.
- spine, locations, rendition 흐름이 이미 라이브러리 수준으로 축적돼 있다.

2. 정밀 위치 관리
- CFI, locations, 레이아웃 리플로우 기반 이동이 더 성숙하다.
- 문서 구조가 복잡한 책에서 앵커 안정성이 더 좋다.

3. 범용 리더 기능
- 주석, 하이라이트, 북마크, 본문 검색 같은 부가 기능을 붙이기 쉽다.
- 외부 EPUB 파일의 다양성을 넓게 받아들인다.

4. 유지보수 관점
- EPUB 렌더링 특수 케이스를 라이브러리 쪽에서 흡수한다.
- 자체 구현은 기능이 늘수록 회귀 테스트 부담이 커진다.

## 3. 현재 수준의 판단

1. 서비스 전용 리더로는 충분히 강하다.
- 지금 구현은 BookOasis의 실제 사용 패턴에 맞춰져 있다.
- 모바일 안정성과 이어읽기 품질은 이미 실사용 수준이다.

2. epub.js 완전 대체는 아직 아니다.
- 범용 EPUB 엔진으로서의 호환성 폭은 아직 epub.js가 우세하다.
- 특히 예외 EPUB, 복잡한 레이아웃, 향후 확장 기능에서 차이가 난다.

3. 결론은 부분 대체 가능.
- "우리 서비스에서 쓰는 EPUB 읽기"는 대체 가능성이 높다.
- "일반 EPUB 뷰어 라이브러리" 대체는 아직 보수적으로 봐야 한다.

## 4. 2026-08-25 업데이트 — 만화 뷰어 대비 상대 평가

배경: 만화 뷰어는 원격(rclone/구글 드라이브) 라이브러리 기준으로 타 솔루션(Kavita 등) 대비 체감 속도에서 압도적이라는 평가를 받는 반면, EPUB 뷰어는 상대적으로 Kavita류에 밀린다는 평이 있음. 두 뷰어가 같은 서비스 안에서 비교되는 만큼, "부분 대체로 충분하다"는 2번 항목의 판단 기준을 유지하되 격차 원인을 더 구체적으로 짚어야 함.

1. v2.3.0 이후 격차가 좁혀진 부분
- 하이라이트(형광펜) 기능 추가 — 데스크톱 페이지/스크롤 모드 모두 지원, 우클릭/롱프레스 컨텍스트 메뉴에 플러그인 확장 지점(옵시디언/노션 내보내기 등)까지 붙음.
- 모바일에서는 터치 충돌 문제로 하이라이트가 꺼져 있음(2026-08-23, 3차례 수정 시도 실패 후 비활성화) — Kavita와 비교 시 모바일 사용자에게는 여전히 공백으로 체감됨.
- 챕터 프리페치 배치화로 로딩 체감 속도 개선(2026-08-18 확인 완료).

2. 여전히 비어 있는 항목 (Kavita 대비 실제 격차의 핵심)
- 본문 검색(전체 텍스트 검색) 기능이 없음 — 코드베이스에 검색 관련 뷰어 모듈 자체가 없음(하이라이트 anchor 유틸만 존재).
- 북마크(하이라이트와 별개의 "이 위치 표시" 기능)가 없음.
- 예외 EPUB(복잡한 CSS, 세로쓰기, RTL, 비표준 마크업) 대응은 문서화된 회귀 테스트 세트가 아직 없음.

3. 판단
- 만화 뷰어의 "속도 우위"는 원격 스토리지 최적화(스캔/스트리밍 경로)에서 나온 것이라 EPUB에 그대로 적용되지 않음 — EPUB 격차는 속도보다 기능 완성도(검색/북마크) 문제로 재정의해야 함.
