# EPUB.js 대체를 위한 단계별 보강 로드맵

## 1. 우선 보강할 항목

1. 정밀 위치 복원
- CFI, href, spine index, percent의 우선순위를 더 명확히 한다.
- 리플로우 후에도 동일 위치를 재현할 수 있어야 한다.

2. 레이아웃 안정성
- 페이지/스크롤 전환, 회전, 주소창 변화에서 위치가 흔들리지 않아야 한다.
- 모바일에서 첫 페이지 점프나 초기화 현상을 완전히 제거해야 한다.

3. 텍스트 탐색
- 본문 검색, 챕터 내 이동, 하이라이트 기반 점프를 강화한다.
- TOC 선택과 현재 읽는 위치의 동기화를 더 단단하게 만든다.

4. 예외 EPUB 대응
- 이미지, 복잡한 CSS, 비표준 마크업, RTL, 세로쓰기 대응 범위를 넓힌다.
- 실패 시 복구 경로를 표준화한다.

## 2. 기능 확장 순서

1. 현재 UX 고정
- 모바일 뒤로가기, 오버레이, 이어읽기, 페이지/스크롤 전환을 회귀 없이 고정한다.
- 이 단계에서는 기능 추가보다 안정화가 우선이다.

2. 표준 기능 보강
- 하이라이트, 북마크, 검색, 위치 공유 같은 리더 기본 기능을 추가한다.
- 가능하면 서버에 독립된 상태 모델로 저장한다.

3. 호환성 검증
- 샘플 EPUB 세트로 회귀 테스트를 만든다.
- 일반 도서, 만화형 EPUB, 이미지 위주 EPUB, 복잡한 TOC EPUB를 구분해 검증한다.

4. 대체 범위 확정
- 서비스 내부 전용으로 쓸지, 외부 일반 EPUB까지 받을지 범위를 문서화한다.
- 범위가 넓을수록 epub.js 유지 가치가 커진다.

## 3. 현실적인 권장안

1. 단기
- epub.js 완전 대체를 목표로 두지 말고, 현재 커스텀 리더를 서비스 전용 엔진으로 강화한다.

2. 중기
- 사용자 체감이 큰 기능만 추가한다.
- 검색, 북마크, 하이라이트, 위치 공유 정도가 우선순위다.

3. 장기
- 외부 EPUB 호환성 요구가 커질 때만 epub.js 재도입 여부를 재평가한다.

## 4. 2026-08-25 업데이트 — 재우선순위화

만화 뷰어는 원격 드라이브 기준 속도에서 이미 우위를 인정받는 상황이라, EPUB 쪽 개선 여력을 "기능 완성도" 격차를 좁히는 데 집중하는 게 맞다. 아래는 위 로드맵 항목들의 현재 진행 상태와 재우선순위.

1. 완료된 항목
- 하이라이트(형광펜) 기능 — v2.3.0에서 데스크톱 페이지/스크롤 모드 모두 지원, 우클릭/롱프레스 플러그인 확장 지점까지 포함해 "표준 기능 보강" 1순위 항목을 사실상 완료.
- 텍스트 프리페치/캐시 성능 — 배치 API 전환으로 챕터 로딩 체감 속도 개선 완료(2026-08-18 사용자 확인).
- TXT/EPUB 2페이지 모드 재진입/홀수 컬럼 버그 다수 수정 — "레이아웃 안정성" 항목의 상당 부분 커버.

2. 진행 중 / 보류
- 모바일 하이라이트는 터치 충돌로 비활성화 상태(2026-08-23) — 재설계 필요하나 서두르지 않기로 함(3회 연속 quick-fix 실패 이력).

3. 재우선순위 (기존 "표준 기능 보강" 순서를 아래로 갱신)
- 1순위: 본문 검색 — 현재 전혀 없는 기능. Kavita 대비 체감 격차의 핵심으로 지목됨. 챕터별로 이미 분리 제공되는 텍스트를 그대로 활용하면 서버 사이드 인덱싱 없이도 클라이언트 챕터 단위 검색부터 시작 가능.
- 2순위: 북마크 — 하이라이트와 별도로 "지금 위치 저장" 개념이 없음. epub_session의 CFI/href/index/percent 저장 구조를 재사용하면 구현 비용이 낮음.
- 3순위: 예외 EPUB 회귀 테스트 세트 — 일반 도서/만화형 EPUB/이미지 위주 EPUB/복잡한 TOC EPUB 샘플을 모아 회귀 기준을 문서화(3-3 항목, 아직 착수 전).
- 4순위: 모바일 하이라이트 재설계 — 위 세 항목 이후, 조급하게 재시도하지 말 것.

4. 착수 순서는 "체감 격차 크기"가 아니라 "구현 난이도/리스크" 기준으로 재정렬함
- 검색은 격차 크기는 크지만 구현 표면이 넓다(챕터 순회 매칭, 원격 마운트 지연 로딩 챕터를 검색 전 미리 당겨와야 하는 문제 등) — 설계만 먼저 정리하고 실제 착수는 별도 세션에서.
- 북마크는 격차 크기는 검색보다 작지만 기존 구조 재사용도가 높아 구현 리스크가 낮다 — 먼저 착수.
- → 실제 작업 순서: **북마크 → 검색 설계 → 검색 구현 → 예외 EPUB 테스트 세트 → 모바일 하이라이트**.

## 5. 북마크 기능 상세 설계 (착수 대상)

1. 데이터 모델
- 하이라이트와 별개 개념: "지금 위치를 표식으로 저장"만 하는 가벼운 기능. 별도 테이블(예: `epub_bookmarks` 또는 기존 `annotation` 계열 테이블에 `type=bookmark` 구분) 필요 — 하이라이트 스키마를 억지로 재사용하지 말고 최소 컬럼(book_id, user_id, cfi/href/chapter_idx/percent, label, created_at)으로 새로 둘 것.
- 위치 저장 방식은 `epub_session`이 이어읽기 복원에 쓰는 CFI/href/index/percent 우선순위 로직을 그대로 재사용 — 새 위치 계산 로직을 만들 필요 없음.

2. UI 배치 — 기존 목차 패널에 탭 추가
- 대상: [txt_toc.js](static/js/viewer/txt_toc.js)의 `renderEpubTocPanel()`이 만드는 `epub-toc-container` / `epub-toc-btn` 플로팅 패널.
- 새 버튼을 만들지 않고, 패널 헤더에 "목차 / 북마크" 탭 2개를 추가해 같은 패널·같은 토글 버튼을 공유(오버레이 메뉴의 nav/layout/style/margin 탭과는 별개 — 그쪽은 이미 4탭이라 붐비고 성격도 "도구 설정"이라 다름).
- 북마크 탭 콘텐츠: 목차 리스트와 동일한 아이템 UI(제목 텍스트 + 클릭 시 점프)에 "삭제" 버튼만 추가. 현재 위치를 저장하는 "+ 북마크 추가" 버튼은 오버레이 메뉴 nav 탭의 기존 버튼 행(처음부터/읽음 완료/마지막으로) 옆에 추가하는 게 자연스러움.
- TXT 뷰어에도 동일 패널이 있으므로([txt_toc.js](static/js/viewer/txt_toc.js) 기준 TOC 없는 TXT도 챕터 구조는 있음) TXT/EPUB 공통 기능으로 구현 가능 — 만화(zip/cbz)는 페이지 번호 기반으로 별도 검토 필요(범위에서 제외하고 우선 TXT/EPUB만).

3. API
- 기존 하이라이트 API 라우트 옆에 `/api/epub-bookmarks` 계열 CRUD 엔드포인트 추가(패턴은 하이라이트 라우트 재사용).

4. 모바일 화면 밀도 검토 결과 (2026-08-25, FIX)
- 목차/북마크 패널(고정 300px, 오른쪽 슬라이드)은 모바일 화면(360~430px 폭)에서 이미 거의 전체 폭을 차지하고 풀 높이라, 탭 2개 추가는 폭·높이 모두 문제없음 — 그대로 진행.
- 실제 타이트한 지점은 오버레이 메뉴 nav 탭의 버튼 줄(처음부터/읽음완료/마지막으로) — `overlay-controls-row`가 `flex-wrap`이라 깨지진 않지만(tab_media_library_viewer.css:629), 세로 짧은 모바일 가로모드에서 줄바꿈이 읽기 영역을 누름.
- **결정(FIX)**: "+북마크" 버튼은 텍스트 라벨 없이 아이콘 전용(★)으로 만들어 이 줄에 추가한다. 다른 대안(별도 줄, 별도 버튼 위치 등)은 재검토하지 않는다.

5. 다음 단계
- 이 설계를 바탕으로 다음 세션에서 구현 착수. 모바일 UX는 하이라이트만큼 복잡한 터치 제스처가 없으므로(클릭/탭 한 번짜리 리스트 UI) 모바일 비활성화 없이 처음부터 모바일 포함해서 만들 것.
