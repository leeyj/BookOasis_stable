# EPUB.js 대체 판단 기준표

## 1. 대체 가능

1. BookOasis 전용 EPUB 읽기
- 내부에서 생성/정제하는 EPUB 위주라면 현재 구조로 충분하다.
- 모바일 UX와 이어읽기 품질이 더 중요하다.

2. 제한된 기능의 전자책 뷰어
- 챕터 탐색, TOC, 페이지/스크롤 전환, 진행률 저장이 핵심이면 가능하다.
- 서버 연동 중심의 가벼운 리더로는 이미 적합하다.

## 2. 조건부 대체

1. 검색과 북마크를 추가할 수 있을 때
- 본문 검색, 북마크, 하이라이트가 들어가면 사용성은 크게 올라간다.
- 다만 구현 범위가 넓어질수록 유지비가 커진다.

2. EPUB 샘플 군이 제한적일 때
- 포맷이 제각각인 외부 EPUB를 광범위하게 받지 않는다면 대체 가능성이 높다.
- 사내/서비스 내 표준 도서만 다루면 커스텀 구현이 유리하다.

## 3. 대체 비권장

1. 범용 EPUB 엔진이 필요할 때
- 외부 유입 EPUB를 폭넓게 받아야 하면 epub.js가 더 안전하다.
- 표준 호환성에서 커스텀 구현은 불리하다.

2. 접근성/국제화/복잡 레이아웃이 중요할 때
- RTL, 세로쓰기, 복잡한 스타일 문서, 특수 레이아웃은 검증 비용이 크다.
- 이 경우 라이브러리 기반이 장기적으로 유리하다.

## 4. 최종 판단

1. 서비스 전용 대체는 가능성이 높다.
2. 범용 epub.js 완전 대체는 아직 보수적으로 봐야 한다.
3. 가장 현실적인 전략은 "epub.js 제거"가 아니라 "필요 기능만 계속 보강하는 자체 EPUB 엔진"이다.
