# 음악 모드 설계 (오디오북 세션 확장)

작성일: 2026-10-02 · 상태: 1·2단계 구현, 3단계 일부(상세 트랙 표·커버 정사각) — 테스트 서버(.21) 배포, 미커밋

## 1. 목표와 원칙

BookOasis가 호평받는 이유는 사람이 생각하는 순서를 그대로 따라가기 때문이다.

> 카테고리 정하기 → 폴더 추가 → 스캔 → 바로 읽기

음악도 똑같아야 한다.

> **카테고리 만들 때 속성 "음악" 선택 → 음악 폴더 지정 → 스캔 → 앨범 카드 눌러 바로 재생**

- **폴더 = 앨범, 폴더 이름 = 제목.** 사용자가 드라이브에서 보던 이름이 그대로 카드에 뜬다. 태그로 앨범을 다시 묶지 않는다.
- **새 세션을 만들지 않는다.** 오디오북 세션의 스캔·커버·스트리밍·트랜스코딩·rclone 최적화·미니 플레이어를 그대로 쓴다.
- **추천·믹스·아티스트/장르 탐색·가사·라디오는 범위 밖이다.** 필요해지면 나중에 따로 다룬다.

### 계기: Sorix 시험 결과 (2026-10-02, 테스트 서버 :4540)

- 라이브러리 추가가 `관리자 > 관리자 메뉴 > 서버 설정 > 라이브러리 추가` 안에 숨어 있었다.
- 스캔한 100곡이 `[멜론] 2026.08 월간 TOP 100 FLAC` 대신 **"RESCENE – SCENEDROME" 앨범**으로 등록됐다. 첫 파일의 태그로 앨범 정보를 정하는 방식 때문이다. 스캔 자체는 성공했지만 사용자는 곡을 찾을 수 없었다.
- 라이브러리와 재생 목록이 따로 놀아서, 추가한 뒤 바로 재생으로 이어지지 않았다.

폴더 이름을 제목으로 쓰는 오디오북 방식이었다면 세 가지 모두 생기지 않았을 문제다.

## 2. 사용자 흐름

| 단계 | 사용자 행동 | 지금 오디오북 | 음악 모드에서 바뀌는 점 |
|---|---|---|---|
| 1 | 오디오북 세션에서 카테고리 추가, 속성 **음악** 선택 | 속성 목록이 비어 있음 | 기본 제공 속성 `music` 추가 |
| 2 | 폴더 지정(예: `GDRIVE/MUSIC`) → 저장하면 스캔 시작 | 같음 | 없음 |
| 3 | 앨범 카드 그리드 | 같음 | 레이블만 "트랙/아티스트"로 |
| 4 | 카드 탭 → 첫 곡부터 재생, 상세에서 곡 선택 재생 | 이어듣기 위치에서 재생 | 처음부터 재생, 셔플/반복 제공 |

## 3. 판단 기준: 카테고리 속성(`content_kind`)

- `libraries.content_kind` 와 `library_kinds` 는 이미 있다. 카테고리를 만들 때 고르는 "속성"이다.
- 오디오북 세션의 `_seed_library_kinds`(`services/db_migration_service.py`)는 지금 아무것도 심지 않는다. 여기에 기본 제공(`is_builtin=1`, 삭제 불가) 속성 `music` / "음악"을 추가한다.
- 화면과 API의 판단식은 **`db_type == 'audiobook' and content_kind == 'music'`** 하나로 통일한다. 예: `CategoryService.is_music_library(library)`.
- 플러그인도 이 값을 읽을 수 있다. 기존 `content_kind` 계약을 그대로 따른다.

검토했다가 택하지 않은 안:
- **별도 `music` 세션(db_type):** 권한·라우트·DB·사이드바 등 `'audiobook'` 분기 21곳 이상을 복제해야 한다. 비용이 너무 크다.
- **라이브러리에 새 플래그 컬럼 추가:** 속성 개념과 겹친다. 카테고리를 만들 때 고르는 흐름에도 맞지 않는다.

## 4. 스캔 (`services/audiobook_scanner.py`)

음악 카테고리일 때만 아래가 달라진다. 오디오북 동작은 그대로 둔다.

1. **디스크 폴더 합치기.** `CD1`, `Disc 2` 같은 하위 폴더는 부모 앨범의 일부로 본다.
   - 지금은 부모 폴더에 오디오 파일이 없으면 `CD1`, `CD2`가 각각 별도 앨범이 된다.
   - 디스크 폴더만 가진 부모를 앨범 단위로 잡고, `parse_audiobook_folder`의 `os.walk`로 하위 파일까지 모은다.
   - 트랙 순서는 (디스크, 파일명 자연 정렬)이다.
2. **트랙 제목.** 이미 duration을 읽으려고 여는 `mutagen.File` 결과에서 `title`, `artist` 태그를 함께 읽는다. 태그가 없으면 파일명을 쓰되 앞 번호(`001 `, `01. `)는 뗀다.
   - 앨범을 묶는 데는 태그를 쓰지 않고, **곡 표시에만** 쓴다.
3. **커버.** 기존 폴더 이미지 탐지(`cover/folder/poster`) → 없으면 **첫 트랙의 내장 아트**(mutagen) → 없으면 지금의 대체 SVG.
   - 내장 아트는 첫 트랙 하나만 읽는다. 원격 I/O를 최소로 하기 위해서다.
4. **앨범 아티스트.** 오디오북의 `작가 - 제목` 폴더명 분리는 **쓰지 않는다**.
   - 이유: 실제 스캔에서 `[2018.12.24 싱글EP] A'NDY to Z - 선호하다`가 저자/제목으로 잘못 쪼개졌다. 앨범 이름에는 ` - `가 흔하다.
   - 대신 트랙 아티스트 태그 다수결(절반 이상)을 쓰고, 그것도 안 되면 비워 둔다.
   - 비워 두면 "Various Artists" 같은 가짜 이름을 만들지 않는다.

### 스키마 변경 (`docs/change_db_guide.md` 절차대로)

- `audiobook_tracks.title TEXT NULL`, `audiobook_tracks.artist TEXT NULL`. 둘 다 nullable이라 기존 오디오북 행은 영향을 받지 않는다.
- SQLite는 `_SCHEMA_SQL`, MariaDB는 `MARIADB_CENTRAL_SCHEMA` 와 `_ensure_mariadb_columns` 를 고친다.
- 기존 음악 카테고리의 트랙 제목은 "강제 재스캔"으로 채운다. 백필 함수는 만들지 않는다.

## 5. 재생 (`static/js/audio_player.js` + `audio_player_modules/`)

`openAudioPlayer` 가 받는 메타에 `is_music` 를 싣고, 플레이어는 그 값으로 분기한다.

| 항목 | 오디오북 | 음악 모드 |
|---|---|---|
| 시작 위치 | 마지막 트랙·시각 | 누른 곡의 처음(카드는 1번 트랙) |
| 진행 저장(`progress_sync`) | 주기 저장 | **저장 안 함.** 최근 재생 앨범 기록만 남김 |
| 완료 배지 | 표시 | 표시 안 함 |
| 배속 | 표시 | 숨김(1.0 고정) |
| ±15초 버튼 | 표시 | 이전/다음 곡으로 대체 |
| 셔플 | 없음 | 앨범 안 셔플 |
| 반복 | 없음 | 끔 / 전체 / 한 곡 |
| 앨범 끝 | 정지 | 정지. 반복이 "전체"면 처음부터 다시 |
| 챕터 목록 | "챕터 N" | 곡 제목 · 아티스트 · 길이 |
| 잠금화면(mediaSession) | 책 제목/저자 | 곡 제목 / 트랙 아티스트 / 앨범 |

- 셔플과 반복 상태는 기기별 `localStorage` 에 둔다. 서버에 저장하지 않는다.
- 미니 플레이어, 백그라운드 재생, AudioContext 복구 로직은 그대로 쓴다. 오디오북에서 이미 휴대폰 검증을 마쳤다.

## 6. 화면

- 카드, 상세, 총계 문구의 "권/챕터/저자/청취 완료"를 "앨범/트랙/아티스트"로 바꾼다. i18n 키를 `*_music` 로 추가한다.
- 상세 화면의 트랙 목록에서 각 줄을 누르면 그 곡부터 재생한다. 기존 `detail/interactions.js` 경로를 쓴다.
- 대시보드 "이어 듣기"에는 음악 카테고리를 넣지 않는다. 진행 개념이 없기 때문이다.

### 구현 중 추가된 것 (2026-10-02)

- **카드 커버 정사각.** 기존 비율은 기본(책 표지 세로형)/와이드(16:9)뿐이라 앨범 아트가 잘렸다. 커버 비율에 정사각(1:1)을 추가했고, 음악 카테고리는 설정과 무관하게 항상 정사각이다(`static/js/utils/cover_ratio.js`).
- **트랙 제목 이스케이프.** 챕터 드로어와 상세 트랙 표가 제목을 그대로 innerHTML에 넣고 있었다. 곡 태그(파일 안의 임의 문자열)가 제목이 되므로 이스케이프했다.
- **FLAC 재생 실패 수정.** 멜론 차트 FLAC(24bit/96kHz)의 앨범 아트(PICTURE) 블록이 깨져 있어 Chrome이 `DEMUXER_ERROR_COULD_NOT_OPEN`으로 파일을 열지 못했다. 서버가 FLAC을 보낼 때 STREAMINFO·SEEKTABLE만 남긴 헤더 + 원본 오디오 프레임으로 보내도록 했다(`api/routes/audiobook_routes.py::_flac_clean_layout`). 변환이 아니라 바이트를 이어 붙이는 방식이라 CPU 비용이 없고 Range 탐색도 그대로다. 오디오북 FLAC에도 적용된다.
- **곡별 커버.** 차트 모음은 곡마다 원래 앨범이 다르다. 음악 카테고리 트랙은 `cover_image`가 `/api/media/audiobooks/<aid>/tracks/<tid>/cover`(그 곡의 내장 아트, 없으면 앨범 커버)이고, 플레이어·미니 플레이어·잠금화면이 재생 중인 곡의 커버를 보여 준다(`static/js/audio_player_modules/track_cover.js`). 2024.08 차트 12곡 중 11곡에 아트가 있었다(10종). 트랙 목록에는 곡별 썸네일을 넣지 않았다. 원격에서 곡 100개를 처음 여는 데 곡당 2~6초가 걸리기 때문이다.
- **album.yaml + 가사.** 음악 카테고리 스캔은 앨범 폴더의 `album.yaml`에서 아티스트·발매일·레이블·소개와 (태그가 없는 곡의) 곡 제목을 채운다. 제목은 폴더 이름 원칙 그대로다. 가사는 DB에 저장하지 않고 재생할 때 읽는다(`services/music_lyrics_service.py`, `GET /api/media/audiobooks/<aid>/tracks/<tid>/lyrics`). 순서는 album.yaml(제목으로 매칭, 실패하면 곡 수가 같을 때 순서) → 곡 파일 태그(FLAC/Ogg `lyrics`, MP3 `USLT`, M4A `©lyr`, 싱크 가사 우선)다. 플레이어의 [Lyrics]를 누르면 커버 자리에 가사가 나오고, 싱크 가사는 현재 줄을 강조하며 따라 스크롤한다. 줄을 누르면 그 시각으로 이동한다(`static/js/audio_player_modules/lyrics_panel.js`).
- **상세 머리(3단계).** 음악 앨범 상세는 정사각 커버, `아티스트 · N곡 · 총 길이 · 연도 · 장르` 한 줄(연도·장르는 album.yaml → 외부 조회 결과), [재생](항상 1번 곡부터) [셔플 재생] [재스캔]만 둔다. ISBN/출판사/권/연재 상태/별점/청취 완료/메타 검색/유사 메타데이터 추천은 숨기고, 소개가 없으면 문구도 숨긴다(`static/js/detail/header_view.js` isMusicContext).
- **원격 음악은 스캔 때 곡 파일을 열지 않는다.** 측정 결과, rclone VFS(`--vfs-cache-mode full`, `--vfs-read-chunk-size 256M`, `--buffer-size 32M`)에서는 태그만 읽어도 곡 파일 전체를 내려받았다(25MB FLAC → 25MB, 11초). 공유 드라이브(GDS) 부담 때문에 음악 + 원격 마운트(`is_remote_path`)이면 스캔은 폴더 목록·크기·수정시각과 album.yaml만 쓴다.
  - 곡 제목은 album.yaml(곡 수가 같을 때 순서) → 파일명 순이다. 길이는 0이다.
  - 커버는 폴더 이미지 → album.yaml 포스터 URL(외부라 GDS 요청 없음) 순이다. 내장 아트는 쓰지 않는다.
  - **재생할 때 채운다**(`services/music_enrich_service.py`): 길이 0인 곡이 스트리밍되면 15초 뒤, 이미 캐시된 그 파일에서 길이·태그 제목/아티스트를 채운다. 앨범 아티스트(곡 다수결)와 포스터(그 곡의 내장 아트)는 비어 있을 때만 채운다. 재스캔해도 채운 포스터를 지우지 않는다.
  - 상세 화면은 길이를 모르는 곡을 `-`로 보이고, 총 재생시간은 모든 곡 길이를 알 때만 보인다.
  - 실측(테스트 서버 Aimyon 16장·71곡·3.4GB): 스캔 0.11초, rclone 캐시 증가 0KB. 한 곡을 재생하자 길이 194.1초와 아티스트가 채워졌다.
  - 로컬 디스크 음악 카테고리는 지금처럼 스캔 때 태그를 읽는다. **오디오북 스캔도 같은 구조라 GDS의 오디오북은 첫 스캔에 파일 전체를 받는다** - 아직 손대지 않았다(별도 검토).
- **`album.yaml` 형식.** 사용자 GDrive 음악 폴더(가수/앨범 구조)에는 앨범마다 `album.yaml`이 있고, 가수 폴더에는 `artist.yaml`이 있다. 차트 모음 폴더에는 없고, 곡 태그에 가사가 들어 있다.

## 7. 범위 밖 (필요해지면 따로)

- 여러 앨범 이어 재생, 카테고리 전체 셔플. 2단계 후보 1순위다.
- 재생 목록. 기존 **컬렉션**이 이미 `audiobook_id` 를 담을 수 있어서, "앨범 묶음 재생 목록"은 컬렉션 재생으로 풀 수 있다.
- 태그 기반 아티스트/장르 탐색, 추천, 믹스, 가사, 갭리스 재생, 이퀄라이저.
- 유튜브/라디오. 2026-08 음악 플러그인 결정과는 별개로 둔다.

## 8. 단계

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 1 | 속성 `music` 시드, `is_music_library`, 스캐너(디스크 합치기·태그 제목·내장 커버), 스키마 2컬럼 | 단위 테스트(디스크 폴더/태그 없는 파일/내장 커버), 테스트 서버에서 `GDRIVE/MUSIC` 스캔 |

| 3 | 레이블/i18n, 상세 트랙 목록, 대시보드 제외, 문서(guide_admin, spec_db_schema, CHANGELOG) | 화면 확인 |

## 9. 확인할 위험

- **고음질 FLAC 첫 재생 지연:** 24bit/96kHz FLAC은 곡당 약 70MB다. GDrive(rclone)에서 첫 바이트까지의 지연을 테스트 서버 slow path(:5941)로 잰다. 범위 요청이라 전체를 받지는 않는다.
- **iOS Safari FLAC:** 지원 대상이다. 다만 `_needs_audio_transcode` probe 결과가 어떻게 나오는지 확인한다.
- **스캔 비용:** 태그는 이미 여는 mutagen 결과를 재사용하므로 추가 I/O가 없다. 내장 아트는 앨범당 1회만 읽는다.
- **큰 폴더:** 차트 100곡처럼 트랙 수가 많은 앨범에서 곡 목록이 길어지므로 스크롤 성능을 본다.
