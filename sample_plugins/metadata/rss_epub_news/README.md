# RSS 뉴스 EPUB 수집 (rss_epub_news)

매일 아침 읽을 **"내 뉴스 브리핑"** 을 한 권의 EPUB으로 만들어 서재에 꽂아 주는 샘플 플러그인입니다.

수집기 플러그인은 대개 웹툰·소설 같은 엔터테인먼트용으로 쓰이지만, 같은 방식으로
**업무·학습·관심 분야의 정보 피드**도 서재에서 읽을 수 있다는 점을 보여주는 것이 이 샘플의 목적입니다.
읽던 책 옆에 오늘의 브리핑이 한 권으로 꽂히고, 기기를 바꿔도 읽던 위치가 이어집니다.

## 동작

```
RSS 피드 → (SSRF 가드로 fetch) → 파싱 → HTML 정제 → EPUB 생성 → 라이브러리 폴더 저장 → 스캔 큐 등록
```

- 피드가 전문(`content:encoded`)을 주면 본문까지, 요약만 주면 요약 + 원문 링크를 수록합니다.
- 제목·링크만 주는 피드(예: 구글 뉴스 RSS)는 헤드라인 브리핑 형태가 됩니다. **기사 원문 스크래핑은 하지 않습니다.**
- 이미지는 EPUB에 내장하고(옵션), 피드별 책은 첫 이미지가 표지가 됩니다.
- 피드마다 한 권(시리즈)으로 만들거나, **모든 피드를 하루 한 권으로 합칠 수** 있습니다(목차에 `[피드이름]` 표시).
  합친 책은 책 이름과 날짜가 들어간 **생성 표지**(날짜마다 색이 달라 호수 구분 가능)를 씁니다. 앱 번들 폰트(`static/fonts`)와
  Pillow가 있어야 하며, 없으면 첫 기사 이미지로 대체됩니다.
- 하루 한 번 자동 수집(지정 시각 이후)과 설정 화면의 "지금 수집" 버튼을 지원합니다.

## 설정

| 항목 | 설명 |
|---|---|
| RSS 피드 목록 | `이름\|URL` 또는 URL만, 여러 개는 `;` 구분 |
| 저장할 라이브러리 ID | 일반 도서 라이브러리 중 **로컬 경로**가 있는 것 (GDrive 전용 불가) |
| 모든 피드를 한 권으로 | 하루 한 권 "브리핑"으로 합치기 + 책 이름 |
| 수집 시각 / 최대 기사 수 / 이미지 포함 / 자동 수집 | — |

저장 위치: `<라이브러리 로컬 루트>/<이름>/<이름>_<YYYY-MM-DD>.epub`

## 외부 도메인 등록이 필요한가요?

아니요. 설정 → "외부 도메인" 허용 목록은 **브라우저 웹뷰 프록시 전용**이라, 플러그인이 서버에서 보내는
요청에는 적용되지 않습니다. 대신 이 플러그인은 `services/ssrf_guard.py`의
`fetch_public_url_with_redirect_revalidation`을 사용해 **사설/루프백 IP 접근과 리다이렉트를 매번 재검증**합니다
(사용자가 입력한 피드 URL로 내부망을 찌르는 것을 막기 위함). 이 샘플은 어떤 피드도 기본 제공하지 않습니다.

## 만들 때 겪기 쉬운 함정 (플러그인 개발자용)

- `settings.html`이 있으면 `config_schema` 필드가 **자동 렌더링되지 않습니다.** 입력창을 `settings.html`에 직접
  `name="KEY"`로 넣어야 합니다.
- 설정 저장은 `input` / `select`만 수집합니다. **`textarea`는 저장되지 않으므로** 여러 값은 `;` 같은 구분자로
  한 줄 입력에 담으세요.
- 앱 워커(gunicorn)가 여러 개라 `start_background_service`가 워커마다 호출됩니다. 하루 한 번만 돌려야 하는 작업은
  날짜별 lock 파일(`O_EXCL`)처럼 원자적으로 선점하세요.
- 외부 HTML은 그대로 EPUB에 넣지 말고 허용 태그 화이트리스트로 정제하세요(`script`, 이벤트 속성, `iframe` 제거).
- 이 샘플은 `scanner_queue`, `CategoryRepository`, `ssrf_guard` 같은 **코어 내부를 직접 import** 합니다.
  공식 플러그인 계약이 아니므로 코어 변경에 영향받을 수 있습니다.

## 저작권

RSS로 제공되는 내용은 각 매체의 저작물입니다. 생성한 EPUB은 **개인 열람용**으로만 사용하고 재배포하지 마세요.
