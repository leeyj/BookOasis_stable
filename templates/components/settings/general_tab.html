기본 시스템 설정

북오아시스 미디어 서버의 전반적인 환경설정을 직접 관리할 수 있습니다.

화면 및 뷰어 환경 설정

보관함의 도서 커버 크기를 120px ~ 240px 범위 내에서 본인 모니터 해상도에 최적화하여 조절합니다.

무한 스크롤 및 보관함 로딩 시 한 화면에 렌더링할 도서 카드의 단위 개수입니다.

이미지 로드 시작 후 로딩 오버레이가 나타날 때까지 대기할 지연 시간입니다.

백그라운드 스캐너 설정

MB

이 크기를 초과하는 ZIP/CBZ 파일은 스캔을 건너뛰고 오류 리포트에 기록합니다. 0 = 제한 없음. (기본값: 300 MB)

MB

1회 백그라운드 스캔 회차에서 처리할 수 있는 최대 누적 파일 용량입니다. 0 = 제한 없음. (기본값: 1024 MB)

건

1회 Lazy 스캔 실행마다 ffprobe로 재생시간/해상도를 분석할 영상 강좌 에피소드 최대 건수입니다. 원격 드라이브에서 느린 파일이 섞여 있으면 값이 클수록 책 커버 스캔이 그만큼 늦게 시작됩니다. (기본값: 300건, 서버가 자주 재시작되는 환경이라면 값을 줄이세요)

개

ffprobe 분석을 몇 개씩 동시에 돌릴지입니다. ffprobe는 파일을 읽어들이는 대기 시간이 대부분이라, 원격(rclone) 드라이브에서 값을 올리면 처리 속도가 크게 빨라집니다. 너무 높이면 원격 저장소 쪽 동시 요청 제한에 걸릴 수 있습니다. (기본값: 4)

도서 스캔 시 제외할 파일 및 디렉토리 패턴을 한 줄에 하나씩 입력하세요.
디렉토리는 끝에 /를 붙여 명시할 수 있습니다. (예: @eaDir/, #recycle/, *.tmp, *.sample.cbz)
폴더 내 .bookoasisignore 파일로도 개별 설정 가능합니다.

커버 저장 경로

비워두면 기존과 동일하게 프로젝트 내 ./covers에 저장됩니다. 다른 마운트된 디스크로 바꾸려면 그 경로의 절대경로를 입력하세요. Docker 환경이면 이 경로를 컨테이너 안에도 별도 볼륨으로 마운트해야 합니다 (라이브러리 물리 경로와 동일한 책임 분담). 저장 즉시(재시작 없이) 새 커버부터 이 경로에 쌓이기 시작하며, 기존에 저장된 커버 파일은 자동으로 옮겨지지 않습니다 — 아래 버튼으로 명시적으로 이관하세요.

커스텀 테마

서버의 themes/ 디렉토리에 규격에 맞는 .yaml 파일을 넣으면 "내 설정" 탭의 테마 선택 목록에 자동으로 나타납니다. 작성 규격은 themes/README.md를 참고하세요. 파일을 새로 넣거나 수정했다면 아래 버튼으로 다시 스캔하세요 (서버 재시작 불필요).

시스템 및 메모리 리소스 설정

시스템 가용 메모리가 이 값 미만으로 떨어지면 스캔을 중단합니다. (기본 1536MB)

프로세스 점유 메모리가 이 값을 초과할 경우 스캔을 안전 재시작합니다. (기본 2048MB)

자동 스캔 등 "몇 시에 실행할지" 크론 예약 시각에만 적용됩니다. 스캔완료시각 등 화면에 표시되는 타임스탬프의 기준시간대를 바꾸려면 docker-compose.yml의 TZ 환경변수를 함께 설정하세요.

네트워크 및 보안 설정

[경고] 리버스 프록시(Authentik, Authelia 등)가 앞단에 구축된 홈랩 환경에서만 활성화하세요.

영상 강좌 트랜스코딩 설정 (실험적)

자동 재생 정책 (수동 스위치 없음)
1) 브라우저가 원본을 직접 재생할 수 있으면(mp4/webm + H.264/VP8/VP9 + AAC/Opus 등) 항상 원본을 그대로 스트리밍합니다.
2) 직접 재생이 안 되는 파일(MKV 컨테이너 등)만 아래 ffmpeg 폴백을 자동으로 거칩니다.
3) 폴백 시 기본은 CPU(libx264) 인코딩이며, 아래 점검에서 VAAPI가 감지되면 자동으로 VAAPI 인코딩을 사용합니다.
각 항목별 실제 재생 가능 여부는 스캔 후 백그라운드(Lazy) 분석이 끝나야 확정됩니다.

서버(컨테이너)에서 ffmpeg가 VAAPI 하드웨어 가속을 실제로 사용할 수 있는지(빌드 지원 + 인코더 + /dev/dri 디바이스 패스스루 + vainfo 드라이버 응답)를 단계별로 점검합니다. 도커라면 docker-compose.yml에 devices: - /dev/dri:/dev/dri가 있어야 디바이스가 잡힙니다. 점검 버튼을 누르면 이 서버 경로 값도 함께 저장되고, 결과가 즉시 실제 스트리밍 판단에도 반영됩니다.

비워두면 기본값(-c:v libx264 -preset veryfast -crf 23 -c:a aac -b:a 128k, CPU 소프트웨어 인코딩)을 사용합니다. 입력/출력 파일 인자는 서버가 자동으로 붙이므로 중간 인코딩 옵션만 적으세요.
NVIDIA GPU(NVENC, 예: P600 등)가 있다면 VAAPI 전용 자동 판별은 별도로 만들지 않았으니, 이 필드에 직접 NVENC 옵션을 넣으면 됩니다(호스트에 NVIDIA 드라이버 + nvidia-container-toolkit 설치 및 docker-compose.yml의 NVIDIA GPU 예약 설정 활성화가 선행되어야 함):
-c:v h264_nvenc -preset p4 -tune ll -c:a aac -b:a 128k
ffmpeg가 이 서버에서 NVENC를 실제로 쓸 수 있는지는 ffmpeg -h encoder=h264_nvenc 및 nvidia-smi 명령을 컨테이너 안에서 직접 실행해 확인하세요(VAAPI처럼 자동 점검 버튼은 제공하지 않습니다).

비워두면 기본값(-vf format=nv12,hwupload -c:v h264_vaapi -qp 24 -c:a aac -b:a 128k)을 사용합니다. -vaapi_device 옵션은 위 디바이스 경로 값을 서버가 자동으로 붙이므로 여기엔 적지 않아도 됩니다.
